# Mission 2: Problem & Product Concept

**Due:** October 1, 2026 by 11:59 p.m. ET · **Points:** 125 (added after staff review)
**Submit:** ATL Cup 2026 submission page. One packet file with team name and mission title.

## Objective

Identify a specific problem and the customer who experiences it. Compare the customer's current alternative, choose one task the product will improve, define the meaningful AI function inside the product, and **begin coding that path now**.

> "The best way to predict the future is to create it." (Peter Drucker)

## Deliverable: Problem & Product Concept Brief

- A concise problem statement naming the target customer, situation, task, friction, consequence, evidence, and remaining assumption.
- A comparison with at least one current solution or workaround and a clear value proposition.
- A one-task product path: entry → action → meaningful result → likely failure or help state.
- The specific function AI performs inside the product, what the customer controls, and a simpler non-AI baseline for comparison.
- A link to the first executable code slice, or a truthful build-state note naming the precise blocker and next code task.
- One customer question to investigate in Mission 3.

## Action items

1. **Refine the problem and product promise.** Complete as a team:
   "When [SITUATION], [TARGET CUSTOMER] tries to [TASK] but [FRICTION], causing [CONSEQUENCE]. We know [EVIDENCE]; we still need to check [ASSUMPTION]."
   - Use an approved observation, conversation, or source. Compare the current solution or workaround. Decide what the product will eliminate, reduce, improve, or create. Check against the approved 2026 challenge brief [link TBC]. No unverified market gaps, invented quotes, or generated statistics presented as fact.
2. **Design and code the first product path.** Sketch entry, core action, result, and recovery/help state. Define what AI does and what the customer reviews or controls. Implement one executable piece in the shared code project. AI may help generate or debug code; the team must inspect, run, test, and change it. Then apply **FACTS**: Feed real evidence and build state, Assess the critique and code, Challenge unsupported claims or broken behavior, Test a simpler or more useful path, Steward the checked version. End with one customer question that could change the decision.

## Pro tips

- Think big, but start with one customer task you can make work during the challenge.
- Describe the customer's improvement, not just a novel feature.
- Treat market size, demand, and competitor gaps as hypotheses until evidence supports them.
- Start coding now. Mission 5 should be a working release, not the first build session.
- AI-assisted building is welcome; a useful AI function must also operate inside the product.

## Example (illustrative, not evidence)

- **Problem:** "When a local retailer receives repeated customer questions during a rush, the owner struggles to turn them into consistent next actions, causing delays and missed follow-up."
- **Current alternative:** Notes, memory, generic chat tools.
- **Product path:** Owner enters the question → AI classifies the need and drafts a next action → owner reviews or changes it → product saves the approved action.
- **Non-AI baseline:** A fixed decision tree.
- **First code slice:** A working input form that produces and displays a test result.
